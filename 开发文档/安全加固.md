# 安全加固 - 实施记录与运维手册

> 版本：v1.0　|　日期：2026-11-26　|　状态：已实施
>
> 关联：`CLAUDE.md`「部署约定」、`开发文档/部署文档.md`
> 背景：公网可访问后的安全配套审查，覆盖 SQL 注入、XSS、越权、高频请求（热点攻击）、信息泄露与服务器暴露面。

## 1. 应用层防护（代码）

| 防护项 | 实现位置 | 说明 |
|---|---|---|
| 接口限流 | `app/core/limits.py`、`app/core/middleware.py` | 滑动窗口，按「IP + 接口」计数；登录 20 次/分、注册 10 次/分、预检 60 次/分、生成 5 次/分、保存 20 次/分；超限返回 429 |
| 请求体上限 | `BodySizeLimitMiddleware` | 默认 1MB，先校验 Content-Length，再按实际读取量兜底；超限 413 |
| 计划体积上限 | `plans.py::validate_save` | `plan_content` 序列化后 ≤ 512KB |
| 生成并发上限 | `plans.py::_GENERATE_SEMAPHORE` | 默认同时 4 个，满则直接 429，不排队 |
| 安全响应头 | `SecurityHeadersMiddleware` | `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy`、CSP；同时移除 `Server` 头 |
| 接口文档关闭 | `main.py` 创建 app 时 | 生产（`APP_ENV=production`）默认关闭 `/docs`、`/redoc`、`/openapi.json` |
| 统一异常兜底 | `main.py::unhandled_exception_handler` | 500 只回通用文案，堆栈仅写日志 |
| 生产禁用万能码 | `main.py::_ensure_default_invite` | 非开发环境不再自动创建 `DEV-DEFAULT` |
| LIKE 通配符转义 | `plans.py::list_plans` | `%`、`_`、`\` 转义，关键词截断 50 字 |

所有阈值均可用环境变量覆盖，见 `.env.example` 的「安全加固」段。

### 已知限制

- **限流为单进程内存实现**：与「单 worker」部署一致；扩多 worker 或加 nginx 多实例时需改用 Redis 等共享存储，`RateLimiterRegistry` 接口保持不变。
- **限流按 IP**：同一出口 IP 后的多个用户共享配额（当前小范围使用可接受）。
- **CSP 允许内联脚本**：页面含内联 `<script>`/`style`，故 `script-src` 保留 `'unsafe-inline'`；后续将内联脚本外置后可收紧。
- **HTTP 明文**：未启用 TLS，密码与 token 在公网明文传输（不买域名/不备案的既定约定）。

## 2. 服务器层加固（运维）

| 项目 | 操作 | 回滚方式 |
|---|---|---|
| fail2ban | 安装并启用 sshd jail：10 分钟内 3 次失败封禁 1 小时（`/etc/fail2ban/jail.local`） | `sudo systemctl stop fail2ban` |
| SSH 密码登录 | 关闭密码与键盘交互登录，root 仅密钥（`/etc/ssh/sshd_config.d/99-hardening.conf`），`MaxAuthTries 3` | 删除该文件后 `sudo systemctl reload ssh` |
| Docker 端口 | `DOCKER-USER` 链丢弃 eth0 入站转发，Docker 发布端口不再绕过 ufw；由 `docker-user-firewall.service` 开机恢复 | `sudo iptables -D DOCKER-USER -i eth0 -j DROP && sudo systemctl disable docker-user-firewall` |
| ufw | 删除 20/21/tcp、9200-9300/tcp，将 8000-9000、9000-9199 收窄为仅 9000/tcp | `sudo ufw allow <端口>/tcp` |
| 文件权限 | `travel.db*` → 600；`/home/ubuntu/backup` → 700，备份文件 → 600 | `chmod 644 travel.db`（不建议） |
| 自动安全更新 | 修正 `/etc/apt/apt.conf.d/50unattended-upgrades` 的 Allowed-Origins，补上 `jammy-security`，此后每日自动安装安全补丁 | 恢复原配置块 |

### 验证命令

```bash
sudo fail2ban-client status sshd
sudo sshd -T | grep -Ei 'passwordauthentication|maxauthtries'
sudo iptables -S DOCKER-USER
sudo ufw status
curl -sI http://127.0.0.1:9000/api/health | grep -Ei 'x-frame|x-content|content-security'
```

## 3. 明确不做（风险接受）

1. **不引入 WAF / nginx 反代**：应用层限流已覆盖主要热点攻击面，避免增加单点与内存开销。
2. **不启用 HTTPS**：不买域名、不备案的既定约定；如后续可接受，建议用 Caddy + 自签或免费证书。
3. **保持 `check` 预检接口公开**：注册页失焦校验的产品要求，已用限流降低批量枚举效率。

## 4. 后续建议

- 依赖定期审计：`uv pip audit` 或 `pip-audit`，随版本升级执行。
- 日志巡检：`sudo journalctl -u travel-plan --since today | grep -E '" (4[0-9]{2}|5[0-9]{2})'`，异常增多时排查来源 IP。
- 重启窗口时执行未生效的内核类安全更新。

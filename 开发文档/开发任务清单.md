# 开发任务清单

> 版本：v1.0　|　日期：2026-11-20　|　状态：已确认
>
> 依据：全部需求文档 + `数据库设计.md` v1.2 + `接口文档.md` v1.0 + `邀请码管理.md` v1.1 + `CLAUDE.md`
>
> 组织方式：**垂直切片**——每个阶段把一组功能的前后端同时做完并当场验证，而不是「前端全做完再联调」。

## 1. 顺序调整说明

原计划的 5 步顺序（前端全部 → 注册登录 → 生成/PDF → 历史记录 → 联调）有两处需要调整：

| 原顺序问题 | 影响 | 调整 |
|---|---|---|
| PDF 导出排在历史记录之前 | PDF 依赖已保存的计划 ID，此时数据库无数据，只能用假 ID 硬造 | PDF 移到「保存 + 历史记录」之后 |
| 前端全部先行 | 无接口可接只能 mock，字段不一致集中在最后爆发 | 阶段 0 只做「静态拆分 + 公共层」，业务对接跟随各阶段 |
| 缺少工程骨架、提示词工程 | 后期返工 | 新增阶段 0，提示词单独设任务 |

**推荐顺序**：骨架 → 账号 → 生成 → 保存与历史 → PDF → 全流程回归。

## 2. 阶段总览

| 阶段 | 内容 | 可验证标志 |
|---|---|---|
| 0 | 工程骨架与基础设施 | 前后端能跑起来，邀请码命令可用，5 个前端页面可切换 |
| 1 | 账号端到端 | 能注册（带邀请码）、登录、刷新保持登录、退出 |
| 2 | 计划生成端到端 | 填表 → 真实 AI 返回结构化行程并渲染 |
| 3 | 保存与历史记录端到端 | 保存后列表可见、可搜索、可查看详情、可删除 |
| 4 | PDF 导出端到端 | 详情页可下载完整 11 部分 PDF |
| 5 | 回归、测试与部署 | 异常场景全过、部署到服务器 |

依赖关系：

```
阶段0 ──▶ 阶段1 ──▶ 阶段2 ──▶ 阶段3 ──▶ 阶段4 ──▶ 阶段5
                       │           │
                       └── 阶段4 也依赖阶段3 的详情接口
```

## 9. 关键风险与注意事项

| 风险 | 应对 |
|---|---|
| **提示词输出结构不稳定**（最高风险） | 2.3 单独设任务并预留调试时间；用 Pydantic 校验兜底，校验失败按生成失败处理 |
| 生成耗时超 120s | 输出结构变长（v1.4 细化）后 token 显著增加，开发期实测；必要时压缩输出字段或调低天数上限 |
| PDF 渲染库在 Windows 上装不上 | 已确认 reportlab（纯 Python）；4.1 仍需先做中文字体注册的 POC，避免整份 PDF 显示方框 |
| 前端 http 环境剪贴板不可用 | 0.13 阶段就写好 `execCommand` 降级，不要留到部署时才发现 |
| 联调后期字段不一致 | 阶段 0 完成后再写业务代码；所有接口字段严格按《接口文档》，不临场改 |

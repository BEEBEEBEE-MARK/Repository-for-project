# 开发提示词模板

> 版本：v1.0　|　日期：2026-11-20
>
> 用途：向 AI 下达开发任务时，用统一结构减少返工。核心是四件事——**路径准确、现状明确、约束写死、验收可见**。

## 1. 通用结构

```
作为一个[前端 / 后端 / 测试]程序员，请[实现 / 复核并完善] XXX 功能。

【现状判断】
先检查相关文件：
- 已实现 → 复核是否符合需求，补齐缺失与测试，不要推翻可用实现
- 未实现 → 按需求完整实现

【路径】（必须与磁盘一致，逐字核对）
- 页面 / 代码：
- 需求文档：
- 接口 / 设计文档：
- 数据 / 数据库文件：

【技术约束】
- 语言、框架、版本、依赖管理
- 明确禁止项（如：业务数据访问禁止用 sqlite3 手写 SQL）
- 测试位置与数据隔离要求

【必须遵守】（从需求文档提炼 3-8 条铁律，逐字给文案）
- ...

【验收】
- 自动化测试全部通过
- 真实 HTTP / 浏览器走查
- 数据保留或清理的约定
```

## 2. 登录 / 注册后端（修正版）

```
作为一个后端程序员，请实现（或复核并完善）旅梦规划助手的登录/注册功能。

【现状判断】
先检查 backend/app/api/auth.py、app/core/security.py、app/models/user.py：
- 已实现 → 复核是否符合需求，补齐自动化测试，不要推翻可用实现
- 未实现 → 按需求完整实现

【路径】
- 登录注册页：frontend/login.html（frontend/index.html 是登录后的主页面）
- 需求：需求文档/用户登录-需求描述.md、需求文档/用户注册-需求描述.md
- 接口：开发文档/接口文档.md
- 数据库设计：开发文档/数据库设计.md
- 数据库文件：backend/travel.db

【技术约束】
- Python + FastAPI + SQLAlchemy 2.0（业务数据访问禁止用 sqlite3 手写 SQL）
- uv 管理依赖
- 自动化测试放 test/；测试必须使用独立临时数据库，不得污染 backend/travel.db

【必须遵守（详见需求文档，文案逐字一致）】
- 注册
  - 用户名 3-20 位字母/数字/下划线，唯一性判重不区分大小写
  - 保留字 admin / root / administrator 禁止注册
  - 邮箱格式校验 + 全局唯一（不区分大小写），不做邮件验证
  - 密码 6-20 位，必须同时包含字母和数字
  - 邀请码四态校验：存在 / 启用 / 未过期 / 未用满，失败统一提示「邀请码错误」
  - 注册成功不自动登录（不返回 token）
  - 邀请码 used_count +1 与创建用户在同一事务
- 登录
  - 单输入框，含 @ 按邮箱匹配，否则按用户名
  - 记住我 7 天，未勾选 12 小时
  - 连续失败 5 次锁定 5 分钟，锁定期内即使密码正确也拒绝
  - 登录成功清零失败计数；锁定到期后计数重新累计
  - 失败统一提示「用户名或密码错误」
- 响应统一 {code, message, data}，code=0 表示成功

【验收】
- pytest 全部通过并输出统计结果
- 启动服务做真实 HTTP 走查（注册 / 登录 / me / 错误场景）
- 测试数据保留，等待另外通知清理
```

## 3. 其他任务的填充要点

| 任务 | 「必须遵守」应摘录 | 「路径」特别提示 |
|---|---|---|
| PDF 导出 | 11 部分结构、增量内容 20s 预算静默降级、配图失败降级、30s 超时、结果不存档 | `需求文档/旅行计划PDF导出-PRD.md` |
| 我的旅行计划 | 每页 10 条倒序、搜索标题+目的地、硬删除、只增不覆盖、越权 403 | 列表页 `frontend/plans.html`、详情页 `frontend/plan-detail.html` |
| 前端页面 | 复用 `css/base.css` 设计 token、共用 `js/plan-render.js`、路由守卫 | 页面文件按 CLAUDE.md 目录结构 |
| 数据库变更 | 表结构以《数据库设计》为准、外键与索引不可省略 | 建库脚本 `backend/scripts/init_db.py` |

## 4. 提交前自检清单

| # | 检查项 |
|---|---|
| 1 | 所有文件路径**逐字**核对过（连字符、下划线、文件名） |
| 2 | 说明了该功能是否可能已存在，以及已存在时的处理方式 |
| 3 | 技术禁用项写清楚（如禁止 sqlite3 手写 SQL） |
| 4 | 测试数据隔离要求写清楚（不得污染正式库） |
| 5 | 最关键的业务规则直接摘录进提示词，不只写「见文档」 |
| 6 | 验收方式可执行（命令、走查步骤） |
| 7 | 数据保留/清理约定明确 |

## 5. 踩过的坑（本项目实测）

| 坑 | 正确做法 |
|---|---|
| 需求文档路径少了连字符（`用户登录需求描述.md`） | 实际为 `用户登录-需求描述.md` |
| 登录注册页被写成 `index.html` | 实际是 `login.html` |
| 数据库文件名前后不一致（`star_dream.db` → `travel.db`） | 造成一次完整返工，路径必须一次写对 |
| 同一提示词连续发两次 | 第二轮只会重复复核；发现遗漏时直接说「哪里不对」更高效 |
| Windows 终端中文乱码 | 命令前加 `PYTHONUTF8=1` |
| curl 传中文 JSON 编码损坏 | 改用 Python `httpx` 发请求 |

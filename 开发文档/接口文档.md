## 1. 通用约定

### 1.1 基础信息

| 项 | 值 |
|---|---|
| 开发环境 Base URL | `http://localhost:8000` |
| 生产环境 Base URL | 与前端同源（前端由 FastAPI `StaticFiles` 托管，直接用相对路径） |
| 路径前缀 | 统一 `/api` |
| 请求/响应格式 | `application/json`（PDF 导出接口例外，返回文件流） |
| 字段命名 | snake_case |

### 1.2 统一响应格式

```json
{ "code": 0, "message": "ok", "data": {} }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` 成功；失败时等于 HTTP 状态码（400/401/403/404/429/500/504） |
| `message` | string | 可直接展示给用户的中文文案，与需求文档异常表逐字一致 |
| `data` | object \| null | 业务数据；失败时为 `null` |

### 1.3 认证

- 除「注册」「登录」「健康检查」外，所有接口必须携带请求头：

```
Authorization: Bearer <token>
```

- token 为 JWT（HS256），payload 含 `sub`（用户 ID）与 `exp`
- 「记住我」勾选 → 有效期 7 天；未勾选 → 12 小时
- 未携带 / 无效 / 过期 → HTTP 401，`message="未登录或登录已过期"`；前端清除 token 并跳转登录页

### 1.4 错误码总表

| code | 含义 | 前端处理 |
|---|---|---|
| 0 | 成功 | — |
| 400 | 参数错误 | toast 展示 `message`（字段级错误显示在输入框下方） |
| 401 | 未登录 / token 失效 | 清除 token，跳转登录页 |
| 403 | 越权访问他人数据 | toast「无权访问」，返回列表 |
| 404 | 资源不存在 / 接口不存在 | toast 展示 `message` |
| 405 | 请求方法不支持 | toast 展示 `message` |
| 429 | 登录锁定 | toast 展示 `message` |
| 500 | 服务器异常 | toast「网络异常，请稍后重试」 |
| 504 | 处理超时 | toast「生成超时，请重试」/「导出超时，请重试」 |

### 1.5 接口总览

| # | 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|---|
| 1 | POST | `/api/auth/register` | 注册（含邀请码） | ❌ |
| 2 | POST | `/api/auth/login` | 登录 | ❌ |
| 3 | GET | `/api/auth/check` | 注册唯一性预检（失焦校验） | ❌ |
| 4 | GET | `/api/auth/me` | 获取当前登录用户信息 | ✅ |
| 5 | POST | `/api/plans/generate` | 生成旅行计划（不保存） | ✅ |
| 6 | POST | `/api/plans` | 保存计划 | ✅ |
| 7 | GET | `/api/plans` | 计划列表（分页 + 搜索） | ✅ |
| 8 | GET | `/api/plans/{plan_id}` | 计划详情 | ✅ |
| 9 | DELETE | `/api/plans/{plan_id}` | 删除计划 | ✅ |
| 10 | GET | `/api/plans/{plan_id}/pdf` | 导出 PDF | ✅ |
| 11 | GET | `/api/health` | 健康检查（部署用） | ❌ |

## 2. 认证接口

### 2.1 注册

`POST /api/auth/register`

依据：注册 PRD §2、§3、§4（v1.3 含邀请码）

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | ✅ | 3-20 位字母/数字/下划线；判重不区分大小写；禁止 admin/root/administrator |
| `email` | string | ✅ | 邮箱格式；判重不区分大小写 |
| `password` | string | ✅ | 6-20 位，必须含字母和数字，不允许空格 |
| `invite_code` | string | ✅ | 6-20 位字母/数字，校验不区分大小写 |

> 确认密码由前端校验，**后端不接收** `confirm_password`。

```json
{
  "username": "fengzi",
  "email": "fengzi@example.com",
  "password": "abc12345",
  "invite_code": "XK7M2QZ3"
}
```

**成功响应**（不返回 token，注册后需手动登录）

```json
{
  "code": 0,
  "message": "ok",
  "data": { "id": 1, "username": "fengzi", "email": "fengzi@example.com" }
}
```

**校验顺序**（与注册 PRD §2.5 / §4 一致）

1. 用户名格式 → 保留字 → 用户名已存在
2. 邮箱格式 → 邮箱已被注册
3. 密码格式
4. 邀请码：存在 → 启用 → 未过期 → 未用满
5. 全部通过后**同一事务内**：创建用户（写入 `invite_code_id`）+ 邀请码 `used_count + 1`

**失败响应**

| code | message |
|---|---|
| 400 | 用户名需为 3-20 位字母、数字或下划线 |
| 400 | 该用户名为系统保留，请更换 |
| 400 | 用户名已存在 |
| 400 | 请输入正确的邮箱格式 |
| 400 | 邮箱已被注册 |
| 400 | 密码需为 6-20 位，且必须包含字母和数字 |
| 400 | 邀请码错误 |
| 500 | 网络异常，请稍后重试 |

### 2.2 登录

`POST /api/auth/login`

依据：登录 PRD §2、§3、§4、§5

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `account` | string | ✅ | 用户名或邮箱（含 `@` 按邮箱匹配，否则按用户名）；首尾空格去除 |
| `password` | string | ✅ | 不做 trim，精确匹配 |
| `remember_me` | boolean | ❌ | 默认 `false`；`true` 时 token 有效期 7 天，否则 12 小时 |

```json
{ "account": "fengzi", "password": "abc12345", "remember_me": false }
```

**成功响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "expires_in": 43200,
    "user": { "id": 1, "username": "fengzi" }
  }
}
```

`expires_in` 单位秒（12h = 43200，7d = 604800）。

**锁定规则**（登录 PRD §5）

- 同一账号连续失败 5 次 → 锁定 5 分钟，期间**即使密码正确也拒绝**
- 锁定返回 429；登录成功清零失败计数；锁定到期后计数归零

**失败响应**

| code | message |
|---|---|
| 400 | 请输入用户名 |
| 400 | 请输入密码 |
| 401 | 用户名或密码错误 |
| 429 | 尝试次数过多，请 5 分钟后再试 |
| 500 | 网络异常，请稍后重试 |

### 2.4 注册唯一性预检

`GET /api/auth/check`

依据：注册 PRD §4 #1/#2（失焦异步校验）、§5（校验策略）

**查询参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `field` | string | ✅ | `username` 或 `email` |
| `value` | string | ✅ | 待校验的值，首尾空格去除 |

**成功响应**

```json
{ "code": 0, "message": "ok", "data": { "exists": true, "message": "用户名已存在" } }
```

| data 字段 | 说明 |
|---|---|
| `exists` | `true` 表示已被占用或为保留字；`false` 表示可用 |
| `message` | 占用时的提示文案（可用时为空字符串） |

**判定规则**

- 用户名：格式合法 → 保留字判定（`admin` / `root` / `administrator` 视为 `exists=true`，message=「该用户名为系统保留，请更换」）→ 查重（不区分大小写）
- 邮箱：格式合法 → 查重（不区分大小写）

**失败响应**

| code | message |
|---|---|
| 400 | 参数错误（field 不是 username / email） |
| 400 | 请输入内容（value 为空） |
| 400 | 用户名需为 3-20 位字母、数字或下划线 |
| 400 | 请输入正确的邮箱格式 |

> 本接口为公开接口（注册页未登录时调用），只返回「是否被占用」，不返回其他账号信息。已知风险：可被用于探测账号是否存在，本期接受；如需收紧可后续加频率限制。

## 3. 计划生成与保存

### 3.1 生成计划（不保存）

`POST /api/plans/generate`

依据：生成 PRD §3.1~§3.8、§4（v1.5）

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `departure` | string | ✅ | 出发地，1-50 字，首尾空格去除（v1.7 新增） |
| `destination` | string | ✅ | 1-50 字，首尾空格去除；支持多城市（顿号/逗号/斜杠分隔） |
| `days` | int | ✅ | 1-15 |
| `start_date` | string(date) | ❌ | `YYYY-MM-DD`；为空时按「第 1 天…」组织 |
| `budget_per_person` | int | ✅ | 人均预算，正整数，≤999999 |
| `people` | int | ✅ | 1-20，默认 2 |
| `interest_tags` | string[] | ❌ | 取值：历史文化/自然风光/美食/亲子/购物/夜生活/摄影/休闲度假；可多选 |
| `pace` | string | ❌ | 宽松/适中/紧凑，默认「适中」 |
| `transport_pref` | string | ❌ | 公共交通为主/自驾/不限 |
| `hotel_pref` | string | ❌ | 经济型/舒适型/豪华型/不限 |
| `special_needs` | string | ❌ | ≤200 字 |
| `guides` | object[] | ❌ | 参考攻略，1-3 条；每条 `{ "type": "link"\|"text", "content": "..." }`，文本单条 ≤500 字 |

> 链接仅作来源记录、不做后端抓取（合规红线）；只有 `type="text"` 的正文参与生成。

```json
{
  "departure": "上海",
  "destination": "昆明",
  "days": 5,
  "start_date": "2026-04-12",
  "budget_per_person": 3200,
  "people": 2,
  "interest_tags": ["自然风光", "美食", "摄影"],
  "pace": "适中",
  "transport_pref": "公共交通为主",
  "hotel_pref": "舒适型",
  "special_needs": "希望节奏舒缓，少赶路。",
  "guides": [
    { "type": "text", "content": "翠湖免费，文山荷鲜居小锅米线人均约 20…" },
    { "type": "link", "content": "https://example.com/kunming-5days" }
  ]
}
```

**成功响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "title": "昆明 5 日慢游 · 山水与烟火",
    "used_guide": true,
    "plan_content": { "...": "结构见《数据库设计》§6.1" }
  }
}
```

| 字段 | 说明 |
|---|---|
| `title` | 结果页标题，AI 生成；失败降级为「目的地+N 日游」 |
| `used_guide` | 后端实际判断：是否有效使用了攻略正文（全被过滤 / 仅链接时为 `false`，静默降级，不报错） |
| `plan_content` | 完整计划内容，含 `sources`（参考来源列表）与 `accommodations`（住宿推荐，v1.6 新增） |

**超时**：同步等待，上限 120s（正常目标 60s）。超时返回 504，前端提示「生成超时，请重试」。

**失败响应**

| code | message |
|---|---|
| 400 | 请输入目的地 |
| 400 | 出行天数需为 1-15 天 |
| 400 | 请输入人均预算（正整数） |
| 400 | 人数需为 1-20 人 |
| 400 | 参考攻略最多 3 条，每条文本不超过 500 字 |
| 401 | 未登录或登录已过期 |
| 500 | 生成失败，请重试 |
| 500 | 网络异常，请稍后重试 |
| 504 | 生成超时，请重试 |

> 「重新生成」复用本接口（生成 PRD §3.6），不自动保存，结果替换当前展示。

### 3.2 保存计划

`POST /api/plans`

依据：生成 PRD §3.5、列表 PRD §3.1/§3.6（v1.3）

**关键约定**

- **只增不覆盖**：每次调用插入新记录，不提供更新接口
- `title` / `summary` **由后端在保存请求内生成**（AI 轻量调用，目标 1-3s），前端不传；失败降级为规则文案，**不阻塞保存**
- `summary` 降级规则：行程概览首句截断（≤50 字）

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `departure` | string | ✅ | 生成条件（出发地，v1.7 新增） |
| `destination` | string | ✅ | 生成条件 |
| `days` | int | ✅ | 1-15 |
| `start_date` | string(date) | ❌ | |
| `budget_per_person` | int | ✅ | |
| `people` | int | ✅ | 1-20 |
| `interest_tags` | string[] | ❌ | |
| `pace` | string | ❌ | |
| `transport_pref` | string | ❌ | |
| `hotel_pref` | string | ❌ | |
| `special_needs` | string | ❌ | |
| `used_guide` | boolean | ✅ | 来自生成接口返回值 |
| `guide_sources` | object[] | ❌ | 参考来源元信息（只存类型与链接，**不传正文**）：`[{ "type": "link", "url": "...", "label": "分享链接" }]` |
| `plan_content` | object | ✅ | 生成接口返回的 `plan_content` 原样回传 |

**成功响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": 12,
    "title": "昆明 5 日慢游 · 山水与烟火",
    "summary": "五天走遍滇池、石林与老街，在温和的节奏里感受春城的花与味。",
    "created_at": "2026-11-19T07:42:00Z"
  }
}
```

**失败响应**

| code | message |
|---|---|
| 400 | 参数错误（具体字段说明） |
| 401 | 未登录或登录已过期 |
| 500 | 保存失败，请重试 |

## 5. PDF 导出

### 5.1 导出 PDF

`GET /api/plans/{plan_id}/pdf`

依据：PDF PRD §3.1~§3.6、§4、§5（v1.5）

**说明**

- 仅能导出**本人**已保存的计划（生成结果页未保存时该按钮不出现，所以只处理已保存记录）
- 每次即时生成、**不存档**、不限次数
- 内部流程：**纯数据渲染，不调用大模型**（2026-11-20 项目要求）→ 从已保存数据组装 11 部分 → reportlab 渲染 PDF
  - 行前准备清单：按天数与季节规则生成
  - 交通信息：复用保存的 `long_distance_transport`
  - 住宿推荐：复用保存的 `accommodations`
  - 景点速查表：由每日安排的 `spot_tips` 重组
- 总超时 30s（实测生成约 0.1s）

**成功响应**：`200`，二进制文件流

```
Content-Type: application/pdf
Content-Disposition: attachment; filename*=UTF-8''%E6%98%86%E6%98%8E5%E6%97%A5%E6%B8%B8_20261119.pdf
```

文件名规则：`目的地+天数日游_导出日期.pdf`（目的地仅保留中英文与数字）。

> **本接口成功时不返回 `{code,message,data}`**（返回二进制流）；**失败时**按统一格式返回 JSON。

**失败响应（JSON）**

| code | message |
|---|---|
| 401 | 未登录或登录已过期 |
| 403 | 无权访问 |
| 404 | 计划不存在 |
| 500 | 导出失败，请重试 |
| 504 | 导出超时，请重试 |

> 当前版本不做图库配图与 LLM 增量，无对应降级路径；内容字段缺失时按空值容错渲染，导出仍成功。

## 7. 无接口的功能说明（易误认为遗漏）

| 功能 | 为何没有接口 | 实现方式 |
|---|---|---|
| 退出登录 | JWT 无状态，服务端不存会话 | 前端删除 localStorage 中的 token 并跳转登录页（登录 PRD §3.6） |
| 复制/分享计划 | 纯浏览器能力，不经过服务端 | `navigator.clipboard` 写入剪贴板，http 环境降级为 `execCommand`（列表 PRD §3.5、部署约定 §6） |
| 主页面跳转 | 纯前端路由 | 静态页面跳转 |
| 生成中离开拦截 | 纯前端行为 | `beforeunload` + 视图切换确认（生成 PRD §3.2） |
| 重新生成 | 复用生成接口 | `POST /api/plans/generate`（生成 PRD §3.6） |
| 表单条件保留 | 前端状态 | 返回表单页时不重置表单（生成 PRD §3.7） |
| 一次生成多次保存 | 只增不覆盖 | 每点一次保存 = 调用一次 `POST /api/plans` |
| 邀请码签发/查看/停用 | 管理口不暴露公网 | 后端 CLI：`uv run python -m app.cli invite ...`（邀请码管理 §3） |
| 邀请码校验 | 无独立接口 | 内嵌在 `POST /api/auth/register` 中 |
| 空状态/加载失败重试 | 前端状态 | 依据列表响应判断（列表 PRD §3.7） |
| 免责声明 | 内容的一部分 | 随 `plan_content` / PDF 返回 |

## 9. 联调注意事项

1. **前端统一封装**：`api.js` 中集中处理 token 注入、`code !== 0` 的 toast、401 跳转登录页；业务代码不直接写 `fetch`。
2. **生成接口耗时**：前端需设置 130s 以上请求超时（后端 120s 兜底），并显示 loading + 禁用按钮；生成中离开需拦截。
3. **PDF 接口**：前端用 `response.blob()` 接收，从 `Content-Disposition` 解析文件名；不能按 JSON 解析。
4. **时间字段**：全部为 UTC ISO 8601（`2026-11-19T07:42:00Z`），前端转本地时区展示；列表显示精确到分钟。
5. **枚举值**：`pace`、`transport_pref`、`hotel_pref`、`interest_tags` 的取值必须与本文档一致（中文定值），前端标签文案直接复用。
6. **plan_content 是前端渲染契约**：字段结构见《数据库设计》§6.1，后端不得增减字段或改字段名；标注码值 `fact/src/cat/feedback` 前端映射为「以实际为准 / 参考来源 / 品类建议 / 来自旅行者反馈」。

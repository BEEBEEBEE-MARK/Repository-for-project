## 1. 机制说明

邀请码用于**阻止陌生人注册**（程序公网可访问，注册会消耗 DeepSeek API 余额）。

- 邀请码由**站长本人**签发，不做申请流程，不通过页面分发
- **没有网页管理后台**：所有管理操作在服务器上通过命令行完成，不向公网暴露管理入口
- 访客在注册页填写邀请码，后端校验通过才允许注册

校验条件（全部满足才有效）：**码存在 + 已启用 + 未过期 + 已用次数 < 最大次数**。任一不满足，统一提示「邀请码错误」（不区分原因，防止试探有效码）。

## 2. 数据表结构

```sql
CREATE TABLE invite_codes (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    code        VARCHAR(20) NOT NULL UNIQUE, -- 统一存大写，校验不区分大小写
    note        VARCHAR(50),                 -- 备注：发给谁 / 用途
    max_uses    INTEGER NOT NULL DEFAULT 1,  -- 最大可用次数
    used_count  INTEGER NOT NULL DEFAULT 0,  -- 已用次数
    expires_at  DATETIME,                    -- 过期时间，NULL = 永不过期
    enabled     BOOLEAN NOT NULL DEFAULT 1,  -- 是否启用
    created_at  DATETIME NOT NULL
);
```

使用者关联：用户表 `users.invite_code_id` 外键指向本表，注册时写入，用于追溯「某码被谁用了」。删除邀请码时该字段自动置空（`ON DELETE SET NULL`），用户账号不受影响。

## 3. 命令手册

所有命令在**服务器 `backend/` 目录**下执行。

### 3.1 生成邀请码

```bash
uv run python -m app.cli invite create --note "老王" --max-uses 1 --days 30
```

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `--note` | 否 | 空 | 备注，建议写发给谁，便于日后追溯 |
| `--max-uses` | 否 | 1 | 可注册人数（朋友聚会可设 3-5） |
| `--days` | 否 | 30 | 有效天数；传 `0` 表示永不过期 |
| `--code` | 否 | 随机生成 | 自定义码（跳过自动生成，不推荐） |

输出示例：

```
已生成邀请码：XK7M2QZ3
  备注：老王　可用 1 次　过期：2026-12-19
把该码发给对方，对方在注册页填写即可。
```

### 3.2 查看全部邀请码

```bash
uv run python -m app.cli invite list
```

输出示例：

```
CODE       备注    使用     状态      过期时间
XK7M2QZ3   老王    1/1     已用尽    2026-12-19
AB9P4TY6   小李    2/5     使用中    2026-12-19
QW3RT7YU   家庭群  0/10    使用中    永不过期
ZX8CV2BN   —       0/1     已停用    —
```

### 3.3 停用 / 启用邀请码

```bash
# 码泄露或不想再让人用 —— 立即失效（已注册用户不受影响）
uv run python -m app.cli invite disable XK7M2QZ3

# 重新启用
uv run python -m app.cli invite enable XK7M2QZ3
```

### 3.4 查看某个码的使用人

```bash
uv run python -m app.cli invite show XK7M2QZ3
```

输出示例：

```
邀请码：XK7M2QZ3（备注：老王）
状态：使用中　2/5　过期：2026-12-19

使用人：
用户名    邮箱                 注册时间
zhangsan  zhangsan@example.com  2026-11-20 10:12
lisi      lisi@example.com      2026-11-21 18:03
```

用于核对「这个码到底被哪些人用了」，发现陌生账号立即 `disable` 并联系核实。

### 3.5 删除邀请码（可选）

```bash
uv run python -m app.cli invite delete XK7M2QZ3
```

> 删除是物理删除。一般用 `disable` 即可，保留记录便于追溯。

## 4. 完整使用流程

### 场景一：邀请一位朋友

1. SSH 登录服务器，进入 `backend/` 目录
2. 执行签发命令，记下屏幕输出的码：
   ```bash
   uv run python -m app.cli invite create --note "老王" --max-uses 1 --days 30
   ```
3. 把地址和码发给朋友：`http://你的公网IP:8000` + `XK7M2QZ3`
4. 对方注册页填写用户名、邮箱、密码、邀请码 → 注册成功
5. 该码已用次数变为 1，`max_uses=1` 时自动失效，无法再被使用

### 场景二：一次邀请一群人

```bash
uv run python -m app.cli invite create --note "家庭群" --max-uses 10 --days 7
```

同一个码发给 10 个人，7 天内用完即止。**不适合大范围公开传播**，泄露后码会被陌生人消耗。

### 场景三：码泄露了

```bash
uv run python -m app.cli invite disable XK7M2QZ3   # 立即失效
uv run python -m app.cli invite create --note "老王-补发" --max-uses 1 --days 30
```

### 场景四：本地开发时不想每次填码

首次启动后端时会**自动创建一个默认码并把明文打印在后端控制台**：

```
[INIT] 邀请码表为空，已创建默认邀请码：DEV-DEFAULT (可用 999 次，永不过期)
```

本地开发直接填这个码即可。生产环境首次启动后，建议用 `disable` 停用它，再签发正式码。

## 5. 安全建议

1. **一码一人**：默认 `--max-uses 1`，泄露影响面最小
2. **设过期**：默认 30 天，避免长期有效的码被翻出来用
3. **定期 `list` + `show` 巡检**：发现某码被用完却不是你发的人，立即 `disable`，并用 `show` 查出使用人
4. **不要写进公开仓库 / 聊天群公告**，只私发
5. 邀请码只防陌生人注册，**不防已注册用户滥用 AI 接口**——频率限制属于后续版本（见生成 PRD 边界约定）

## 6. 常见问题

| 问题 | 说明 |
|---|---|
| 用户反馈"邀请码错误" | 依次检查：码是否输错、是否已用尽（`list` 查看）、是否过期、是否被停用 |
| 改码需要重启服务吗？ | 不需要。数据库即时生效 |
| 能改已发放码的最大次数吗？ | 当前不提供修改命令，可 `disable` 后重新签发 |
| 邀请码会存在用户表里吗？ | 会。用户表 `invite_code_id` 记录注册所用邀请码，可用 `invite show <码>` 查看使用人 |
| 忘记了自己签发过哪些码？ | 执行 `uv run python -m app.cli invite list` |

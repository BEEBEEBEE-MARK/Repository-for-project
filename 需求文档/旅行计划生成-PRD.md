## 1. 功能概述

本功能是系统的核心：用户在"旅行计划生成页"填写出行条件，由后端调用大模型 API 生成结构化旅行计划，展示后可保存。覆盖**输入表单、生成触发、加载状态、结果展示、保存、重新生成、返回**七大流程，另含**攻略参考**增强能力（用户选填提交攻略，见 3.8）。

- 生成方式：**同步等待**（后端拿完整结构化结果再返回，前端 loading 动画 + 120s 超时兜底）
- 未登录访问本页面 → 跳转登录页（全局路由守卫，见《主页面-需求描述.md》）

## 2. 功能列表

| # | 流程 | 概要 |
|---|---|---|
| 1 | 输入表单 | 12 项出行条件，核心五项必填（出发地/目的地/天数/预算/人数），其余选填 |
| 2 | 生成触发 | 点击"生成计划"提交，前端校验通过后请求后端 |
| 3 | 加载状态 | 生成中 loading 动画、防重复提交、120s 超时 |

| 6 | 重新生成 | 基于当前条件手动重新生成，不自动保存 |
| 7 | 返回 | 返回表单页，保留已填条件 |

## 3. 详细描述

### 3.1 输入表单

| 字段 | 必填 | 规格 |
|---|---|---|
| 出发地 | ✅ | 自由文本，1-50 字，placeholder 示例"上海"，首尾空格去除；用于生成往返交通 |
| 目的地 | ✅ | 自由文本，1-50 字，placeholder 示例"昆明"；**支持多个城市**，用顿号/逗号/斜杠分隔（如"哈尔滨、长春、沈阳"），系统按顺序分配天数并生成城际交通 |
| 出行天数 | ✅ | 数字 1-15，超出范围提示"出行天数需为 1-15 天" |
| 出发日期 | ⬜ | 输入框显示与录入格式统一为 `yyyy/mm/dd`（可点击右侧日历图标选择）；未填时行程按"第 1 天、第 2 天…"组织 |
| 预算 | ✅ | 人均数字输入（元/人），正整数，上限 999999 |
| 人数 | ✅ | 数字 1-20，默认 2 |
| 兴趣偏好 | ⬜ | 固定标签多选：历史文化/自然风光/美食/亲子/购物/夜生活/摄影/休闲度假 |
| 行程节奏 | ⬜ | 单选：宽松/适中/紧凑，默认"适中" |
| 交通偏好 | ⬜ | 单选：公共交通为主/自驾/不限 |
| 住宿偏好 | ⬜ | 单选：经济型/舒适型/豪华型/不限 |
| 饮食/特殊需求 | ⬜ | 自由文本 ≤200 字，字数实时统计 |
| 参考攻略 | ⬜ | 折叠展开式选填区；1-3 条，每条为分享**链接**或**粘贴正文文本**（文本每条 ≤500 字）；链接仅作来源记录，粘贴文本参与生成（详见 3.8） |

校验规则：
- 必填项为空 → 对应输入框下方提示"请输入/请选择 XXX"
- 格式类错误前端即时校验，全部通过后方可提交
- 输入项遵循**最小化收集**原则，不收集姓名、手机号、证件号等个人信息
- 参考攻略超过 3 条或单条文本超 500 字 → 提示"参考攻略最多 3 条，每条文本不超过 500 字"

### 3.2 生成触发与加载状态

- 点击"生成计划"→ 前端校验 → 提交后端 → 后端调用大模型 API → 返回完整结构化 JSON
- **防重复提交**：生成中按钮置为 loading 并禁用，禁止重复点击
- **超时**：120 秒未返回 → 提示"生成超时，请重试"，可手动重试
- **离开确认**：生成中离开/切换页面/刷新/关闭标签页均拦截（beforeunload），弹确认框"生成中，离开将丢失本次结果"

### 3.3 结果展示

结果页按以下模块展示（均来自 AI 结构化输出）：

| 模块 | 内容 |
|---|---|
| 行程概览 | 目的地、天数、整体主题建议、预算汇总 |
| 交通信息 | **长途交通**：去程（出发地 → 首个目的地）、返程（最后目的地 → 出发地）、城际段（相邻城市之间）；每段含 2-3 种交通方式（时长/费用）与推荐理由（详见 3.3.3） |
| 每日安排 | 按天分块；每日内按时间块（上午/下午/晚间）组织，每块含：地点/活动、景点提示、交通方式对比、附近美食、餐饮、分项预算、备注（子结构详见 3.3.1） |
| 住宿推荐 | 2-3 条住宿方案，**按推荐优先级排序**；每条含：住宿区域、酒店品牌或类型、档次（经济型/舒适型/豪华型）、价格区间、一句话推荐理由；优先匹配用户的住宿偏好（详见 3.3.2） |
| 预算估算 | 分项（交通/住宿/餐饮/门票/其他）+ 汇总 |
| 注意事项 | **仅目的地通用层**：天气提醒、安全提示、文化习俗等；景点专属提示已下沉至每日安排对应景点条目（见 3.3.1）；参考攻略踩雷帖按所属景点挂至对应条目并标注"来自旅行者反馈"，目的地级踩雷保留在本模块 |
| 备选建议 | 两层：**当日层**（对应景点/时段遇排队、闭馆、天气不适时的当日替换选项，展示在每日安排对应天）+ **全局层**（同目的地整体替换的景点/活动建议） |
| 免责声明 | 页面固定展示："行程与价格均为 AI 估算，信息非实时，出行前请自行核实"；本次生成使用了参考攻略时追加："参考内容来自公开分享，可能过时或夸大，仅供灵感参考" |

#### 3.3.1 每日安排子结构（v1.4 细化）

每个时段块（含具体景点/活动时）在原"地点/活动、餐饮、分项预算、备注"基础上，新增以下子结构。信息按**三档口径**输出（按幻觉风险分级，与 3.4 对应）：

| 子结构 | 内容 | 无参考攻略时 | 有参考攻略时 |
|---|---|---|---|
| 景点提示 | 是否需预约/限流、建议游览时长、最佳游览时段、门票价格区间、装备/着装提示 | 给出；实时性信息（门票等）标注"以实际为准" | 同左，有依据部分标注"参考来源" |
| 交通方式对比 | 到达该景点 2-3 种可选方式（如地铁/打车/公交），各含预计时长与费用，末尾给**推荐方式及理由**（省时/省钱/舒适） | 定性对比与推荐始终给出；具体线路、票价标注"以实际为准" | 具体线路与价位依攻略提炼，标注"参考来源" |
| 附近美食 | 景点周边就餐推荐，2-4 条，**必须为具体店名** | 给出当地知名或常见的**具体店铺**：店名/招牌菜/距景点距离（估算）/人均价位，标注"以实际为准" | 优先使用攻略中提到的店铺：店名/招牌菜/距景点距离（估算）/人均价位，标注"参考来源" |

口径说明：
- 原"交通"字段升级为"交通方式对比"；原"餐饮"字段保留（当日正餐安排），与"附近美食"（就近就餐推荐）分工互补
- 备选建议**当日层**展示在每日安排对应天；全局层保留在"备选建议"模块
- 注意事项的景点专属层已全部下沉至本结构，全局模块不再重复展示
- **附近美食口径（v1.6 调整）**：无论是否有参考攻略，都必须给出具体店名，不再允许只写"当地特色小吃"这类泛称。无攻略依据时统一标注"以实际为准"；确无把握的个别条目可用"品类 + 街区"表述，但不得编造店名

#### 3.3.2 住宿推荐（v1.6 新增）

| 字段 | 说明 |
|---|---|
| 推荐排序 | 2-3 条，按推荐优先级从高到低排列，界面显示 1/2/3 序号 |
| 住宿区域 | 结合行程动线的区域建议（如"春熙路/太古里周边"） |
| 酒店品牌或类型 | 具体品牌（如"全季/亚朵等连锁"），无把握时可写类型 |
| 档次 | 经济型 / 舒适型 / 豪华型，优先匹配用户"住宿偏好"；未指定时给出 2-3 个不同档次 |
| 价格区间 | 如"¥400-600/晚"，标注为估算 |
| 推荐理由 | 一句话，说明交通、位置或适合人群 |
| 标注 | 有攻略依据标"参考来源"，否则标"以实际为准" |

#### 3.3.3 交通信息（v1.7 新增）

展示**城市间长途交通**，与每日安排中的"交通方式对比"（景点间市内交通）分工不同。

| 段 | 说明 |
|---|---|
| 去程 | 出发地 → 首个目的地；2-3 种交通方式（飞机/高铁/动车等），含预计时长与费用，给出推荐方式及理由 |
| 返程 | 最后一个目的地 → 出发地；同上 |
| 城际 | 多城市时，相邻城市之间逐段列出（如哈尔滨→长春、长春→沈阳）；单城市时无此项 |

- 标注：有攻略依据标"参考来源"，否则标"以实际为准"
- 价格为估算；城际段数量 = 目的地城市数 - 1

### 3.4 AI 输出要求

- 使用**中文**，**结构化 JSON** 输出，字段固定，便于前端稳定渲染与保存
- 不编造营业时间、票价、政策等实时信息；相关内容标注"以实际为准"
- 明确标注价格为估算、信息非实时
- 不输出违法、危险或不适合的建议（依赖大模型内容安全策略 + 免责声明兜底）
- 生成失败时返回**可读错误信息**（如"生成失败，请重试"），不向前端暴露技术细节
- 在地细节信息按**三档口径**输出（与 3.3.1 对应）：
  - **① 定性建议**（游览顺序、交通方式优劣对比、美食品类等）：始终给出，不依赖参考攻略
  - **② 实时性事实**（门票区间、开放时间、具体线路、票价）：有攻略依据时依攻略提炼并标注"参考来源"；无依据时可给，但必须标注"以实际为准"
  - **③ 门店级推荐**（具体店名、招牌菜、距景点距离、酒店品牌）：有攻略依据时优先使用攻略中的店铺，以原创表述输出（不复制原文）并标注"参考来源"；**无依据时仍须给出当地知名或常见的具体店铺，标注"以实际为准"**（v1.6 调整）；严禁编造不存在的店名，限制使用绝对化断言
- 不使用绝对化断言与无法核实的头衔（如"必吃榜第一""全网最低价"）；距离、时长一律表述为估算

### 3.5 保存

- 结果页提供"保存"按钮，保存对象为当前展示的计划（含生成条件 + 计划内容 + **是否使用参考攻略标记**，标记用于详情页与 PDF 的免责声明口径）
- **只增不覆盖**：每次保存产生一条新记录；已保存记录不做更新/覆盖
- 保存成功 → toast"已保存"，**不跳转**，停留结果页
- 保存成功后，结果页出现"**导出 PDF**"按钮（保存 = 确认心意，见《旅行计划PDF导出-PRD.md》）
- 保存的记录可在"我的旅行计划"列表页查看（见《我的旅行计划-PRD.md》）
- 保存权限：仅当前登录用户本人，记录归属生成时登录账号

### 3.6 重新生成与补充攻略优化

**重新生成**

- 结果页提供"重新生成"按钮，基于当前表单条件发起一次全新生成
- 重新生成**不自动保存**；结果替换当前展示内容
- 重新生成后，"导出 PDF"按钮**隐藏**，重新保存后再次出现——保证"导出内容 = 已保存内容"，避免导出未保存的新结果
- 可多次触发，每次均按 3.2 流程执行（防重复提交同样生效）

**补充攻略优化（v1.8）**

- **生成结果页**：提供"补充攻略"按钮，弹窗输入 1-3 条链接/文本，追加到当前条件后重新生成，**不离开结果页**；补充的条目同步追加到表单攻略区
- **计划详情页**：提供"补充攻略"按钮，基于该已保存计划的出行条件 + 新补充攻略重新生成；结果在原页面展示，标注"优化结果（未保存）"，提供"保存为新计划"与"返回原计划"
- 攻略总条数上限仍为 3 条，单条文本 ≤500 字
- 优化结果**未保存**：导出 PDF 不可用；保存时**只增不覆盖**，原计划不受影响
- **已知限制**：已保存计划仅保留攻略来源元信息（链接与来源类型），原始粘贴正文未存档（数据库设计 §6.2），因此详情页优化时无法复用原有正文，只能补充新内容；原有链接来源可继续携带
- 旧记录若缺少出发地（v1.7 之前保存），详情页补充攻略时提示"该计划缺少出发地信息"
- 原有"返回表单补充攻略"的方式仍然保留

### 3.7 返回

- 结果页提供"返回"入口，回到表单页
- 已填条件**全部保留**，便于微调后重新生成

### 3.8 攻略参考处理（选填增强）

目标：让行程携带真实在地细节，同时过滤广告与风险。处理流水线：

1. **收集**：仅接收用户主动提交的链接/文本，**系统不做任何平台内容自动抓取**（合规红线）
2. **提取**：MVP 阶段链接**不做后端内容提取**，仅作为来源记录与展示；**粘贴文本是唯一可靠内容来源**，直接生效（合规边界：后端不访问平台页面，规避抓取争议）
3. **过滤**：规则层（联系方式/营销话术/外链特征）+ LLM 分类（广告/软广/正常攻略）；广告与软广剔除，同步清洗联系方式等隐私信息
4. **注入**：合格内容作为 RAG 上下文参与生成，提炼要点（地名/玩法/价位/避坑），以原创表述输出，不复制原文
5. **标注**：结果展示"参考来源"链接列表，供用户溯源
6. **降级**：全部内容被过滤或仅提交链接无文本时，静默跳过参考机制，按通用方式正常生成，不提示报错

踩雷帖专项：识别"避雷/踩坑"类负向内容，去重后并入"注意事项"模块，标注"来自旅行者反馈"。

## 4. 异常场景与提示文案

| # | 场景 | 提示文案 | 时机 |
|---|---|---|---|
| 1 | 必填项为空 | 请输入/请选择 XXX（具体到字段） | 前端即时 |
| 2 | 天数/人数/预算超出范围 | 具体提示，如"出行天数需为 1-15 天" | 前端即时 |
| 3 | 生成超时（>120s） | 生成超时，请重试 | 后端/前端超时 |
| 4 | 生成失败（模型异常/内容安全拦截） | 生成失败，请重试 | 后端 |
| 5 | 网络/服务器异常 | 网络异常，请稍后重试（与登录文档一致） | 请求失败时 |
| 6 | 生成中离开页面 | 确认框："生成中，离开将丢失本次结果" | 路由切换/刷新/关闭标签页时 |
| 7 | 保存失败 | 保存失败，请重试 | 保存请求失败时 |
| 8 | 参考攻略超限（>3 条或单条文本 >500 字） | 参考攻略最多 3 条，每条文本不超过 500 字 | 前端即时 |
| 9 | 参考攻略全部无效（被过滤/仅提交链接无文本） | 无提示，静默按通用方式生成 | 后端 |

## 5. 验收标准

1. 未登录状态直接访问生成页，被路由守卫拦截并跳转登录页
2. 目的地、出行天数、预算、人数四项任一为空时无法提交，且对应输入框下方出现具体提示
3. 出行天数输入 0、16 或非数字时，提示"出行天数需为 1-15 天"
4. 生成过程中"生成计划"按钮处于禁用状态，重复点击不触发第二次请求
5. 生成超过 120 秒时展示"生成超时，请重试"，重试可正常发起
6. 生成成功后，结果页完整展示行程概览、每日安排（含时间块/景点提示/交通方式对比/附近美食/餐饮/分项预算）、预算汇总、注意事项（目的地通用层）、备选建议（当日层+全局层）与免责声明
7. 点击"保存"后收到"已保存"toast，后端新增一条记录；再次保存产生第二条记录（不覆盖）
8. 重新生成后展示新结果，未保存时后端记录数不变
9. 结果页 → 返回表单页，此前填写的 12 项条件（含参考攻略）全部保留
10. 生成失败时前端展示可读错误文案，不出现堆栈/技术细节
11. 提交含微信号/营销话术的参考文本时，该内容被过滤不进入生成结果；提交正常攻略文本后，生成结果包含对应景点/店铺细节并展示"参考来源"
12. 参考攻略提交 4 条或单条文本 600 字时，前端即时提示超限文案
13. 仅提交链接未粘贴任何文本时，生成正常完成不受阻塞，"参考来源"仅展示链接记录
14. 每个含景点的时段块包含交通方式对比（≥2 种方式及推荐理由）；未提交参考攻略时定性对比仍正常给出
15. 提交含餐饮门店信息的参考攻略后，对应景点条目下出现店名级附近美食（含招牌/距离/人均）并标注"参考来源"；未提交参考攻略时，附近美食仅为品类建议，不出现编造店名
16. 全局注意事项模块不含景点专属提示（如预约要求出现在对应景点条目下）；当日替换建议出现在每日安排对应天
17. 结果页展示"住宿推荐"模块，含 2-3 条方案并按推荐优先级排序，每条完整展示区域、酒店品牌/类型、档次、价格区间与推荐理由
18. 未提交参考攻略时，附近美食仍展示具体店名（非"当地特色小吃"类泛称），并标注"以实际为准"
19. 出发日期输入框显示占位为 `yyyy/mm/dd`，输入 `2026/5/1` 失焦后规范为 `2026/05/01`；输入非法日期（如 2026/02/30）提示"请输入正确的日期格式（yyyy/mm/dd）"
20. 出发地为空时无法提交，输入框下方提示"请输入出发地"
21. 目的地填写"哈尔滨、长春、沈阳"时，结果页展示交通信息板块，含去程（出发地→哈尔滨）、返程（沈阳→出发地）与 2 段城际交通（哈尔滨→长春、长春→沈阳），各段含 2 种以上交通方式与推荐理由
22. 结果页点击"补充攻略"，弹窗添加 1 条含店名的文本后重新生成：新结果出现该店铺推荐并标注"参考来源"，且"导出 PDF"按钮隐藏
23. 详情页点击"补充攻略"并生成成功后，页面标注"优化结果（未保存）"，显示"保存为新计划 / 返回原计划"；点击保存生成一条新记录并跳转，原记录内容不变（只增不覆盖）

## 6. 非功能性需求

| 类别 | 要求 |
|---|---|
| 性能 | 生成接口同步返回上限 120s；正常目标 60s 内（**v1.4 留痕**：结果结构细化后单次输出 token 增大，60s 目标与 120s 上限需开发期压测复核，必要时一并调整）；loading 期间界面不卡顿 |
| 安全 | 接口登录态校验（未登录返回 401，前端跳登录页）；输入长度限制（目的地 ≤50 字、特殊需求 ≤200 字）防滥用 |
| 隐私合规 | 最小化收集：不收集姓名、手机号、证件号；仅出行条件与偏好 |
| 内容合规 | 免责声明固定展示；AI 不编造实时信息；违法危险内容不出现在结果中 |
| 可用性 | 错误文案全部可读、具体到场景；表单条件在返回后保留 |
| token 成本 | 输入受输入长度限制约束；输出含细化子结构（景点提示/交通对比/附近美食）token 相应增大；本期不做次数限制（见边界约定） |

## 7. 边界约定（本期不做）

- 不做生成频率限制 / 次数配额（防滥用后续版本评估）
- 不做流式输出（打字机效果），采用同步等待
- PDF 导出为独立模块，已成文（《旅行计划PDF导出-PRD.md》）
- 不做任何平台内容的自动抓取；参考攻略仅来自用户主动提交（合规红线）

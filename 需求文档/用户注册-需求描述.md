## 1. 功能概述

用户通过注册页面创建账号，填写用户名、邮箱、密码、确认密码、**邀请码**。注册成功后跳转至登录页。

邀请码说明：程序公网可访问，为防止陌生人注册消耗 AI 接口费用，注册必须持有站长签发的有效邀请码。邀请码由站长在服务器通过命令行生成，**不做申请、不通过页面分发**。

关联说明：本系统登录支持 **用户名或邮箱 + 密码** 两种凭证方式，因此用户名、邮箱均需全局唯一。

## 2. 字段规则

### 2.1 用户名

| 规则项 | 要求 |
|---|---|
| 长度 | 3-20 个字符 |
| 允许字符 | 字母（a-z、A-Z）、数字（0-9）、下划线（_） |
| 唯一性 | 全局唯一，判重时不区分大小写（`Tom` 与 `tom` 视为冲突） |
| 保留字 | 禁止注册：`admin`、`root`、`administrator` |

### 2.2 密码

| 规则项 | 要求 |
|---|---|
| 长度 | 6-20 个字符 |
| 强度 | 必须同时包含字母和数字 |
| 允许字符 | 字母、数字及常见特殊字符（如 `!@#$%^&*`），不允许空格 |

### 2.3 确认密码

- 与密码必须完全一致
- 在密码、确认密码均已填写后校验（失焦或提交时）

### 2.4 邮箱

| 规则项 | 要求 |
|---|---|
| 格式 | 符合标准邮箱格式 |
| 唯一性 | 全局唯一，判重时不区分大小写 |
| 邮箱验证 | **不做邮件验证**，注册即生效 |

### 2.5 邀请码

| 规则项 | 要求 |
|---|---|
| 必填 | ✅ 必填 |
| 长度/字符 | 6-20 位字母或数字 |
| 大小写 | 校验时**不区分大小写**（`xk7m2q` 与 `XK7M2Q` 等价） |
| 有效性条件 | 同时满足：码存在、已启用、未过期、已使用次数 < 最大次数 |
| 使用计数 | 注册成功后该码已用次数 +1；用满后自动失效 |
| 存储 | 注册成功时在用户表记录所用邀请码（`invite_code_id`），**仅用于追溯邀请来源**，不参与登录、权限或页面展示 |
| 签发方式 | 站长在服务器执行命令行生成，见《开发文档/邀请码管理.md》 |

## 3. 正常流程

1. 用户进入注册页（**已登录状态访问注册页，自动跳转主页**），填写用户名、邮箱、密码、确认密码、邀请码
2. 前端格式校验通过后提交
3. 后端校验格式、唯一性与邀请码有效性，通过则创建账号（记录所用邀请码）并累计邀请码使用次数
4. 注册成功 → 跳转登录页，并自动带入刚注册的用户名
5. 注册页提供"去登录"入口，点击跳转登录页
6. 注册成功后**不自动登录**，需用户手动登录

## 4. 异常场景与提示文案

| # | 场景 | 提示文案 | 校验时机 |
|---|---|---|---|
| 1 | 用户名已存在 | 用户名已存在 | 失焦异步校验 + 提交兜底 |
| 2 | 邮箱已被注册 | 邮箱已被注册 | 失焦异步校验 + 提交兜底 |
| 3 | 两次密码不一致 | 密码不一致，请重新输入 | 确认密码失焦 / 提交 |
| 4 | 用户名格式错误 | 提示具体错误，如"用户名需为 3-20 位字母、数字或下划线" | 失焦 / 提交 |
| 5 | 用户名为保留字 | 该用户名为系统保留，请更换 | 失焦 / 提交 |
| 6 | 密码格式错误（长度/强度） | 提示具体错误，如"密码需为 6-20 位，且必须包含字母和数字" | 失焦 / 提交 |
| 7 | 邮箱格式错误 | 请输入正确的邮箱格式 | 失焦 / 提交 |
| 8 | 网络/服务器异常 | 网络异常，请稍后重试 | 提交失败时 |
| 9 | 邀请码为空 | 请输入邀请码 | 提交时 |
| 10 | 邀请码无效（不存在 / 已停用 / 已过期 / 已用满，**统一提示**） | 邀请码错误 | 提交时（后端校验） |

## 5. 交互细节

- **防重复提交**：提交中按钮置为 loading 并禁用
- **空格处理**：用户名、邮箱首尾空格自动去除（密码不做 trim）
- **错误提示位置**：显示在对应输入框下方
- **校验策略**：格式类错误前端即时校验；唯一性类错误后端校验（前端失焦预检 + 提交兜底）
- **邀请码校验时机**：仅提交时校验，**不做失焦校验**（避免用户输入过程中报错）；失败文案统一为"邀请码错误"，不区分具体原因（防止试探有效码）
- **邀请码位置**：确认密码字段之后、提交按钮之前

## 6. 边界约定（本期不做）

- 不做邮箱验证 / 激活流程
- 不做图形验证码（邀请码已承担防陌生人注册职责）
- 不做网页端邀请码管理后台（仅命令行签发，管理口不暴露公网）
- 不做用户申请邀请码流程
